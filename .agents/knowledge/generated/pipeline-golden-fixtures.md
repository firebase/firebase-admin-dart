# Constraint

The JSON files in `packages/google_cloud_firestore/test/fixtures/pipeline_golden/` are generated by the Node.js SDK: `@google-cloud/firestore` at the exact version pinned in `tool/pipeline_golden/package.json`.[^golden-fixtures][^golden-pin]

- `tool/pipeline_golden/cases.js` builds a corpus of named Pipelines with the Node SDK, and `generate.js` writes the request Node sends for each one.[^golden-cases] `generate.js` fails if Node exports a function that has no case.
- `test/pipeline_golden_test.dart` compares every Dart `ExecutePipelineRequest` with the fixtures, in the normal unit run. Every fixture id needs a Dart case, and every Dart case a fixture.
- Exceptions go in three lists in the test: intentional differences in `_knownDivergences` (each with a check), bugs in `_pendingFixes`, and Node APIs Dart can't express in `_dartApiGaps`. Stale entries fail the test. `tool/pipeline_golden/README.md` explains the triage.
- To regenerate, use the Node.js version in the tool's `engines` field: `cd packages/google_cloud_firestore/tool/pipeline_golden && npm ci && npm run generate`, then run `dart test test/pipeline_golden_test.dart`.

# Why

Stated in `tool/pipeline_golden/README.md`: the expected requests "come from the Node SDK itself, never from this package, so a test cannot pass by asserting our own output", and "Never edit the fixtures by hand."

# Enforced by

`.github/workflows/pipeline_golden.yml` regenerates the fixtures and fails on any diff.[^golden-workflow] `test/pipeline_golden_test.dart` runs in the unit run.

# Rules for agents

- **Must:** regenerate and commit the fixtures in the same PR as a change to `cases.js` or to the pinned Node version, and add the matching Dart case.
- **Must not:** edit the JSON under `test/fixtures/pipeline_golden/` by hand.
- **Must not:** "fix" a failing golden test by changing the expectation side.
