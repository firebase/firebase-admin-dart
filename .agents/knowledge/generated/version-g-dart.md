# Constraint

`packages/firebase_admin_sdk/lib/src/version.g.dart` holds `packageVersion`.[^version-file] `scripts/gen-version.sh` writes it from the `version:` in `packages/firebase_admin_sdk/pubspec.yaml`.[^gen-version]

- The file is committed and must match the pubspec exactly.
- It feeds the usage-tracking headers, `fire-admin-dart/<version>` and `fire-admin/<version>`.
- `melos bootstrap` and `melos version` run the script as post hooks, set in the root `pubspec.yaml`.
- `google_cloud_firestore` has no such file. Only the admin package generates one.

# Why

The file header says "GENERATED CODE - DO NOT MODIFY BY HAND". The maintainers have stated that a stale file breaks CI: they updated it specifically to make the publish dry run pass.

The likely mechanism (not recorded): CI's `melos bootstrap` rewrites the file, and `dart pub publish --dry-run` then warns about a modified checked-in file, which fails the dry run.

# Enforced by

The `bootstrap` and `version` post hooks in the root `pubspec.yaml`, and the publish dry run in the `publish` job of `.github/workflows/build.yml`. No test compares the file with the pubspec.

# Rules for agents

- **Must:** every time `firebase_admin_sdk`'s `version:` changes, run `./scripts/gen-version.sh` (or `melos bootstrap`) and commit the result in the same PR.
- **Must not:** hand-edit `version.g.dart`.
